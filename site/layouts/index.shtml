把服务写成模块，
把执行写成运行时。

zmodu 是一个 Zig 框架：路由与依赖在编译期展开，worker 与邮箱在运行时保持有界。 同一份代码可以从单进程的模块化应用，长成一个可重放、可观测的执行平台。

main.zig
const zmodu = @import("zmodu");

pub fn main(init: zmodu.Init) !void {
    var app = try zmodu.builder(init.gpa, init.io)
        .withName("orders")
        .build(.{ order.module });
    defer app.deinit();

    try app.start();
    defer app.stop();
}

能力

框架该在编译期解决的问题，不留到线上。

编译期路由

路由表是一个 comptime 元组。鉴权、权限码、OpenAPI 参数与 handler 同处一行，重复路径在启动前失败。

模块边界

依赖声明由编译器校验：缺失、自依赖、环依赖都在启动时被拦下。单进程先跑通，边界真实了再拆服务。

有界运行时

Worker、Mailbox、MPSC、TimerWheel：状态归一个线程所有，队列满了返回 error.Full，不无限增长。

确定性回放

可控时钟、随机源与事件序列，让同一输入在重放时得到同一顺序与同一输出。

内建可观测

结构化日志、Prometheus 指标、OTLP tracing 与运行时分位读数，默认就在框架里。

AI 与数据

Agent、RAG、审批与配额是可组合的模块；SQLx、Redis、Kafka 与 zent ORM 留在应用层。

声明

一条路由，一行元数据。

handler 只读 ctx 与自己的状态；身份与权限由中间件写入，再在路由表里被审计。

pub const routes = [_]http.RouteSpec(State){
    .{ .method = .GET, .path = "{id}",
       .handler = get, .meta = .{ .auth = .jwt,
                                   .permission = "order:read" } },
};

运行时

一个线程拥有的状态，
一个邮箱拥有的交接。

没有全局锁的 actor 层；定时器由 ticker 独占，跨线程只走命令队列。

const h = try rt.spawn(.{ .capacity = 1024 });
try h.post(.{ .kind = .tick, .at = now + 50 });
// 满了：error.Full，不是内存增长

从一条路由开始，或者从一个 worker 开始。
