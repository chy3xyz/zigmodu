# v0.31.0 → v1.0 差距评估

> 评估基准：**v0.31.0**（tag `ffd9675`，2026-09-20）。
> 与之前那份「能力缺口矩阵」的区别：那份是**按 tag 读代码**写的，这份的每一条都带**实测或断言**的证据，
> 且写明"我验证了什么 / 我没验证什么"。
> 结论一句话：**功能已经不是主要差距了；"能不能证明"才是。**

**一条设计级的发现**（不是功能）：`SchedulerConfig.batch` **不是性能旋钮，它就是公平上界** ——
一个 worker 在忙邻居后面的最坏等待 = 一个 batch。变异（`batch = 1_000_000`）红的是**边界断言**而非超时。

## 二、离 1.0 的真实差距

按**能不能证明**排序，不按功能多少排序 —— 因为功能已经够了。

### A. "证明"这一层（矩阵 §19 的核心，也是最空的一层）

**A1. `runtime-stress` —— 已补（本节写的时候还不存在）。**

当初这一节的原话是"想 soak 时才发现没有工具能 soak 我改的那些东西"。现在有了：`zig build
runtime-stress`（`src/runtime_stress.zig` + `build.zig` 的 step），跑持续负载并周期检查 7 条
不变式 —— 监督守恒（没有成员静默消失）、强度用尽后**停止**重建、阻塞池隔离在长时下成立、
`ready_push_failures == 0`（两池）、热路径零分配、RSS/线程数不单调增长、停机可预测且 claim 全归还。
默认 5 秒，`-Druntime-stress-duration-ms=` 可拉长；三条变异验过红，含**"把负载调轻到断言走不到也会红"**
（空洞的绿是最坏的形状）。

**但这条只补了一半，剩下的一半我说清**：

- **它抓的是稀有竞态与泄漏，不是真实流量形态。** 合成负载无法替代生产流量 —— 后者只能你们在真实环境里跑，
  而**这一条至今仍是零数据**。
- **它本身没有历史。** 一个只跑过几次的 harness 证明不了"长时稳定"，它需要先自己积累一段运行记录
  （夜里挂、跨多个 commit）。在那之前，"`runtime-stress` 绿"只等于"那一次绿"。
- **原有 `zig build soak` 仍是 HTTP/租户隔离**的（实测 64×2000 = 128K 请求只要 6 秒），
  和这条是两件事，不要互相替代。

**A2. 没有跨宿主的一致性证据。** 这一轮所有的性能数字都来自**同一台 aarch64 笔记本**
（而且负载平均 8–10）。CI 有基线文件，但没有"**同一提交在两个不同宿主类上，比值是否稳定**"
这条证据链 —— `StoreForward x10M` 作为 ring 的更贴切参考**就卡在这里**：本机 4.3% vs 6.6%
只能读作"本机更稳"，换不换是需要第二类宿主的数据判断，我从这里证明不了。

**A3. false-red 的风险已被记录，但没有机制。** `TimerWheel x100K`（实测游程散 1.27×，另一组 12 次
到 1.90×）与 hand-off 对（1.84× / 3.09×）都进了 `check-bench.sh` 的"只报告、永不门禁"集合 ——
那个选择是对的，但**代价是它们永远不会提醒你**。缺一条约定：哪条读数是"候选回退，先重跑再修"
（现在这条只写在注释里）。

### B. 功能缺口（按矩阵的排序，我认同）

| 缺口 | 现状 | 为什么它比 A 类低 |
|------|------|------------------|
| **IO 非阻塞化** | 只有**声明式类别**（`.blocking` 走独立池）—— 它解决"声明过的阻塞型 worker 不占 CPU 池"，**不**解决"忘了声明"，也**没有**真正的异步 IO | 需要先有 A1 才能证明改对了 |
| **Replay → WAL / 落盘 / codec** | v1 + 定位筛选；**进程内、内存中** | 需求明确，但它是新存储面，不是"证明" |
| **Deterministic Runtime** | Clock/Sequencer 有了；Random、消息序、定时器序、调度序**未统一受控** | 它是 Replay 的下一层；先要 A1 |
| **Remote Worker / 分布式** | raft 有锁 + 入站窗口；**出站 dial 无界**（std 限制，见下）；传输是自造 TCP | 矩阵自己放 P2 |
| **CPU affinity / μs timer** | 无 | Quant 专用，矩阵放 P2/P3 |

**一条要单独说的既有边界**：`IpAddress.ConnectOptions.timeout` 在 CI 锁定的 Zig 0.17 上
是 **`@panic("TODO implement netConnectIpPosix with timeout")`** —— 实测出来的。
所以 SYN 被丢的对端仍然要付 OS 默认的 connect 超时；补它得自己写带 deadline 的非阻塞 connect + poll。
**这不是框架的选择，是工具链的限制**，但用户最终会撞到它。

### C. 治理 / 流程（矩阵 §19 明确列了，且一件都没做）

```
API freeze 候选        —— 未开始（0.x 期间 Runtime API 允许破坏性演进，这条契约写在 §2）
兼容性审计            —— 未做
安全审计              —— 一次都没有
生产 soak 结论        —— 无数据（见 A1）
```

`API freeze` 的前置是 **A1**：没有长时压测，冻结出来的 API 只是"今天能编译"。

### D. 一条流程问题（不是框架问题，但它直接卡住"可证明"）

这一轮我给两个子代理的简报里都用了 `1303` 当"测试基线"，而**它们是错的** ——
`1303` 是**主二进制**的读数，聚合口径是 `1395/1416`。**两个 agent 各自独立指出并纠正了我**，
没有沉默接受 —— 这是好的，但代价是它们都得先花步数对跑一次。

**"读数口径必须只有一个名字"是"可证明"的前置**。同类问题在 `check-bench` 上也出现过：
一次假红是 `findById` 慢 2.1×，而**机器参考 `atomic RMW` 自己涨了 1.6×** —— 先看参考有没有动，
比看被门禁的指标快得多。这两件都该落成一条写下来的读法约定，而不是每轮重新发现。

## 三、我建议的 1.0 判据（可检查，不是形容词）

```
Correctness    race=0 · double delivery=0 · lost message=0 · lost wakeup=0
               double free=0 · UAF=0                     ← 现有测试已覆盖大部分，缺"长时"
Resource       热路径分配 = 0 · 队列/邮箱/worker 数有界   ← 已在，缺"长时下仍为 0"
Scheduler     no starvation ✅（已断言）· no duplicate execution ✅
              predictable shutdown                        ← 缺长时
Timer         deadline 不提前 ✅ · lateness 有界           ← 有读数，无判据
Replay        same input → same output                    ← 进程内成立；跨重启不成立
Observability 指标齐 ✅（31 条）                            ← 缺 soak 期的守恒式
Performance   benchmark ✅ · baseline ✅ · regression threshold ✅ · CI gate ✅
                                                        ← 缺跨宿主一致性证据
```

**已经打勾的是"单次可证明"，没打勾的是"长时可证明"。** 这就是 1.0 与前夜的分界。

## 四、如果只做一件事

**做 `runtime-stress`（A1）。** 理由：

1. 它是**唯一**能让 v0.31.0 新增的那批东西（监督树 / 阻塞池 / StopPolicy / 池化调度）
   在长时下被检验的工具 —— 而这批东西的共同特征是**"只在稀有交错下出错"**，单次测试与
   短基准**结构上抓不到**。
2. 它是 `API freeze` 与"生产 soak 结论"的共同前置。
3. 它**不需要新功能**，只需要新的**验证** —— 这与矩阵"不要再堆 API"的结论一致。
4. 它能把 A3（false-red 的读法）与 C（治理）从"每轮重新发现"变成"写下来的判据"。

**但要说清它的价值边界**：合成负载抓的是**稀有竞态与泄漏**，它**不能**替代真实流量形态。
我没有你们的真实流量形态，所以我做的只能是前者 —— 后者必须由你们在真实环境里跑。
