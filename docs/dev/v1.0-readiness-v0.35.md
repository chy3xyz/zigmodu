## 五、判断

```text
按"功能 + 安全完成度"      ≈ 1.0 的 88%
   剩下的 12% 里
   ├── A 组（9 条，其中 5 条有界可做）      → 一条条做，可做完
   └── B-11 / B-14（对跑、独立人）          → 这才是门槛
按"能称为 1.0"             ≈ 70%
```

**把 A 组全做完也不会让它变成 1.0。** 1.0 意味着"**可证明**它在生产里站得住"，而证明需要的是
**有人（或某种机制）能推翻我们**：混合版本对跑、独立验证、以及小时级而不是分钟级的持续运行。

### 如果只能做一件

**混合版本对跑（B-11）。**

v0.32 那份的答案是"soak + 混合版本对跑"，**soak 已经做了**（B-10 已关），剩下这一件：

- 它是**唯一**能证伪 cluster/bus 那批改动的实验（v0.32 的原话是"soak 不会，它跑的是另一个子系统"——
  现在 soak 跑的是同一个子系统了，但它**明确不管**混合版本）；
- 它同时是所有多节点部署的**升级路径**问题：现在是硬切，用户升级必须整体停，而"整体停"这件事
  在 3 节点 Raft 上意味着**失去多数派**；
- 它的产物是一个可复现的脚本（旧二进制 + 新二进制对跑，断言"要么拒绝并说清楚，要么正确降级"），
  而不是一段论证。

排第二的是 **A-1（Raft 侧每节点身份）** —— 总线那套握手是现成模板，而它挡着"集群内任何节点都能
冒充任何节点"这条结论；排第三是 **B-14（独立验证）**，它便宜（把复现脚本交给第二个人/另一套工具跑），
但它才是"自证"与"被验证"的分界。
